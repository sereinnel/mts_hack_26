# EnergyTool Frontend v0.4

Frontend для существующего FastAPI-бэкенда МТС EnergyTool. Код находится **только** в `frontend/`; backend не изменяется. Разработка ведётся в ветке `feature/frontend` общего репозитория.

## Запуск на Windows

1. Убедитесь, что FastAPI уже работает на `http://127.0.0.1:8000` (или откройте `http://127.0.0.1:8000/docs`).
2. Откройте CMD/PowerShell в папке `frontend/`.
3. Выполните `npm run dev`.
4. Откройте **http://127.0.0.1:5173/**.

На Windows сервер слушает `127.0.0.1`, а не `localhost`, чтобы избежать известной проблемы IPv4/IPv6. Node.js 18+; `npm install` для этой версии не нужен, так как внешних JS-зависимостей нет.

## Версия 0.4 — интерфейс и исправления

- Поле ввода **всегда находится внизу** основной области, включая пустую сессию, переписку и экран загрузки. История прокручивается отдельно.
- На стартовом экране убрана вторая (встроенная) форма ввода; быстрые темы находятся в прокручиваемой области.
- Сохраняются положение прокрутки, фокус и выделение текста при перерисовках; перед отправкой кнопка заблокирована для пустого сообщения.
- Черновики контактных данных очищаются при переключении сессии; при открытой форме ограничен клавиатурный переход Tab, возвращается фокус после закрытия.
- Статус `AI настроен` обозначает конфигурацию backend, но не гарантирует доступность модели.
- `dev-server.mjs` не раздаёт скрытые файлы, а HTTP-методы вне GET/HEAD отклоняет.
- Мобильная вёрстка проверена на ширинах 390 и 320 px.

## Что поддерживается

- `GET /health`: индикатор режима backend.
- `POST /api/sessions`: новый диалог.
- `GET /api/sessions/{session_id}/messages`: история сообщений.
- `POST /api/chat`: запрос (`session_id`, `message`) и получение `answer`.
- `POST /api/leads`: заявка с явным `consent_to_contact` и подтверждением `id`.
- Локальная история ID сессий без текста переписки и персональных данных.
- Отладка (только на локальном хосте): реальные `sources`, `intent`, `latency_ms`, а будущие поля `stage` и `diagnostics` — при их появлении.

Список всех сессий `GET /api/sessions` не используется в публичном UI, поскольку сервер пока не разграничивает их по пользователям. Административный `GET /api/leads` не используется вовсе.

Важно: backend в демонстрационном состоянии не защищает заявки от дублей на уровне сервера, поэтому повторный POST после обрыва соединения небезопасен. UI не делает его автоматически. Не вводите настоящие контактные данные на публично доступном стенде без серверной защиты.

## Проверка

```bash
npm run check
```

Тесты проверяют контракты запросов и локальное хранение; **не заменяют** ручную проверку браузера и тесты с реальным FastAPI.

## Перенос в общий GitHub

Скопируйте папку `frontend/` в корень уже клонированного `mts_hack_26`, находясь в `feature/frontend`. Не выполняйте `git init` и не создавайте отдельный backend. Если в ветке уже есть правки frontend, сначала сравните их и объедините изменения.

## Обновление с версии 0.3

1. Сохраните копию предыдущего `frontend/` или зафиксируйте текущие изменения в Git.
2. В ветке `feature/frontend` обновите файлы внутри **существующего** `frontend/`; не заменяйте `backend/`, `ai/` или корневые файлы репозитория.
3. Перезапустите `npm run dev` (остановить старый процесс через `Ctrl+C`).
4. Откройте `http://127.0.0.1:5173/` и обновите страницу через `Ctrl+F5`.

При наличии несохранённых собственных правок сначала сравните файлы и объедините изменения.
