# EnergyTool Frontend v0.4 — дизайн и решения

## Главное изменение по обратной связи

**Поле ввода закреплено внизу экрана во всех состояниях.** На пустом экране оно больше не встраивается в стартовый контент. Разделитель и лёгкая тень отделяют нижнюю панель от прокручиваемой области, включая узкие экраны и длинные переписки. За счёт flex-layout поле ввода не перекрывает сообщения.

## Дизайн

- Refined B2B workbench: светлая основная поверхность, нейтральная навигация, один красный акцент.
- IBM Plex Sans / IBM Plex Mono с системными заменами при отсутствии Google Fonts.
- Пустая сессия: заголовок, короткое объяснение, четыре предметных направления, компактная боковая подсказка на широком экране; **единственное** поле ввода снизу.
- Активный диалог: сообщения клиента справа, консультанта слева; рабочее поле снизу не исчезает при ожидании, загрузке истории или ошибках.
- Заявка: адаптивная форма с подтверждением, keyboard focus trap, явное согласие; нет автоматической отправки по сигналу модели.
- Уменьшены анимации при системной настройке reduced motion. На мобильных ширинах закрытый sidebar скрыт также для keyboard focus.

## Исправления логики

- `render()` сохраняет позицию прокрутки, текущий фокус и положение курсора в поле при замене DOM.
- В пустом поле кнопка отправки не активируется; после ввода не требуется обновление всей страницы.
- Контактные данные, набранные в одном диалоге, не переносятся в следующий.
- Неизвестное наличие API-сервисов не выдается за подтверждение работоспособности AI.
- Dev-сервер не выдаёт dotfiles и отклоняет неразрешённые HTTP-методы.

## Совместимость

Не менялись `backend/` и `ai/`, endpoint-ы или JSON-контракты FastAPI. Для `/api/chat` используются `session_id`/`message` и `answer`, для истории `role`/`content`, для заявок `consent_to_contact`. Поля `stage`, `message_id`, `suggested_action`, `diagnostics` остаются необязательными.

## Проверка

Скриншоты созданы в Chromium из настоящего frontend-кода с **имитацией fetch-ответов** (поскольку сетевой переход на localhost блокируется браузерной средой). Контракт реального FastAPI проверен отдельно. Полноценный E2E в браузере на Windows ещё необходим.
