# QA EnergyTool Frontend v0.4

Дата: 2026-11-11

## Проверки, которые фактически выполнены

**JavaScript:** `npm run check` успешно; **9/9** unit-тестов API-контрактов и хранилища. Три JS-модуля проходят `node --check`.

**Chromium + исходные HTML/CSS/JS с mock fetch:** прошли сценарии на 1440×900, 390×780 и 320×650:

- В пустом и заполненном диалоге ровно одно поле ввода; оно располагается внизу viewport; история заканчивается непосредственно перед ним.
- Горизонтальной прокрутки документа нет на проверенных размерах.
- Отправка сообщения создаёт реплику пользователя и ответ консультанта по текущему контракту API.
- Пустую реплику отправить нельзя; после набора текста кнопка активна.
- После переключения debug не пропадает набранный текст и позиция курсора.
- После нескольких сообщений переключение debug сохраняет позицию прокрутки.
- Форма заявки открывается и принимает тестовые данные, согласие и подтверждённый ID; Tab/Shift+Tab остаются внутри диалога.
- Кнопка «Новый диалог» возвращает пустой экран с нижним полем, включая мобильное боковое меню.
- Ошибок выполнения JS (pageerror) при этих сценариях нет.

**Фактический FastAPI из приложенного архивного backend:** отдельно с `TestClient` получены ожидаемые ответы `GET /health` (200), `POST /api/sessions` (201), `POST /api/chat` (200), `GET /api/sessions/{id}/messages` (200, две реплики), `POST /api/leads` (201), `POST /api/sessions/{id}/close` (200). Существующий backend не редактировался.

**Локальный dev-server:** `GET /` и `/src/main.js` — 200; `GET /.gitignore` — 403; `POST /` — 405; `HEAD /` — 200.

## Ограничения проверки

Chromium в среде запрещает переходы на `http://127.0.0.1:5173` (`ERR_BLOCKED_BY_ADMINISTRATOR`). Поэтому визуальные браузерные сценарии выполнены через `page.set_content` из **настоящих** файлов `src/main.js`, `src/styles.css`, `src/api/client.js`, `src/lib/storage.js` с подменой только HTTP-ответов. Это **не полноценный сквозной UI↔FastAPI тест**. Реальный API протестирован отдельно. Не проверялись браузерное сохранение localStorage после перезапуска, реальный сбой AI в браузере, Safari/Firefox и работа мобильной виртуальной клавиатуры.

## Чек-лист на Windows перед Pull Request

1. Запустить существующий FastAPI `http://127.0.0.1:8000` и `frontend/` через `npm run dev`.
2. Открыть `http://127.0.0.1:5173`, проверить поле ввода снизу на пустом экране.
3. Написать вопрос; убедиться, что ответ `mock` появляется и поле не скачет.
4. Отправить 10+ сообщений, прокрутить вверх и включить/выключить debug: позиция не должна прыгать.
5. Перезагрузить страницу: история восстанавливается, старый и новый диалоги независимы.
6. Открыть/закрыть форму заявки, ввести **вымышленные** данные, проверить валидацию, согласие и полученный реальный `id`.
7. Изменить ширину до 390/320px, открыть меню, проверить доступность формы и нижней панели.
8. Проверить ошибку сети/AI и то, что UI не создаёт двойных POST-запросов.

**Backend и AI не изменены.** Из-за отсутствия авторизации у API сессий и идемпотентности заявок не разворачивать стенд для публичного ввода реальных контактов без доработок Backend.
