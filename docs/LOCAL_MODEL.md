# Реальная локальная модель

Для локальной проверки выбран `qwen3:4b-instruct-2507-q4_K_M` через Ollama: около 2,5 ГБ весов, запуск на CPU. Это модель для разработки, а не конкурсная Qwen3.8-27B. Презентация разрешает локальное тестирование с другими LLM.

[Технический регламент организаторов](https://docs.google.com/document/d/1wZsqH4xXZXwjiAJCtFQGjTaLxEU3D_tMCSw0yXcbQ0U/edit) уточняет: при автоматической проверке платформа сама передаёт адрес OpenAI-совместимого прокси, служебный ключ и идентификатор модели через окружение. Личный API-ключ участника не нужен. В конкурсном адаптере нельзя фиксировать имя локальной модели: `ai.llm.LLMConfig` уже читает переменные организаторов.

## Запуск на этом компьютере (Linux и Docker)

Из корня существующего репозитория:

```bash
python -m scripts.start_local_model --host-network \
  --kb 'Данные-20261109T121228Z-1-001/Данные/knowledge-base.zip'

docker compose --env-file data/local_model.env -f compose.yaml -f compose.local-model.yaml up -d --build api
```

Флаг `--env-file data/local_model.env` передаёт Docker Compose выбранные модель и порт; он нужен также при использовании `--model` или `--port`. Без этого флага профиль использует значения по умолчанию. Параметры модели сохраняются отдельно от секретов backend в `.env`.

Первый запуск скачивает официальный образ Ollama и веса модели. Последующие используют кеш `data/ollama/`. Вариант `--host-network` нужен на текущем Linux-компьютере: обычный Docker bridge здесь не обеспечивает доступ к сети. Обе службы слушают только loopback: модель `http://127.0.0.1:11435/v1`, существующий backend `http://127.0.0.1:8000`. Основной `compose.yaml` не меняется; дополнительный файл задаёт подключение и локальный адрес сервера. Облачные функции Ollama отключены через `OLLAMA_NO_CLOUD=1`.

Проверка состояния:

```bash
curl http://127.0.0.1:8000/health
docker logs --tail 30 energytool-llm-local
docker compose --env-file data/local_model.env -f compose.yaml -f compose.local-model.yaml logs --tail 30 api
```

## Прямой вызов AI без backend

Скрипт создаёт игнорируемый `data/local_model.env`. Python самостоятельно этот файл не загружает; перед проверкой импортируйте его в окружение:

```bash
set -a
. data/local_model.env
set +a

python -m scripts.eval_ai --mode llm --limit 3 \
  --kb 'Данные-20261109T121228Z-1-001/Данные/knowledge-base.zip' \
  --questions 'Данные-20261109T121228Z-1-001/Данные/demo_questions.csv' \
  --output data/ai_local_model_smoke.json
```

`generated_answers` считает только ответы, прошедшие генерацию и отдельный вызов семантического Critic. `extractive_fallbacks` и ошибки выводятся отдельно. Сам факт HTTP 200 или одобрение Critic не подтверждают качество консультации: ответы нужно сравнить с вопросами и источниками.

Настройки этого локального профиля: таймаут одного запроса 120 с, максимум 768 выходных токенов, последовательная обработка. Один ответ может потребовать два запроса, поэтому CPU-прогон заметно медленнее извлечения цитат. Нельзя переносить эти задержки и оценки на конкурсную модель.

Проверка 16 ноября: шесть настоящих модельных консультаций, отдельный повтор вопроса после исправления числовой ошибки и два запроса через Docker-backend. Факты предприятия сохранились в общей SQLite, заявки не создавались. Найдены ограничения содержательной проверки: [результаты и замечания](AI_QUALITY.md). Время одного проверенного хода — около 53–91 секунды на CPU.

`LLM_API_KEY=ollama` — несекретное значение для локального API, которое Ollama игнорирует. Служебный ключ платформы подставляется ею отдельно. Веса, БЗ, окружение и отчёты находятся в игнорируемом `data/`, не входят в Git и Docker build context. В контейнер модели БЗ не монтируется; при консультации AI передаёт ей найденные фрагменты локально.

## Остановка

```bash
docker compose --env-file data/local_model.env -f compose.yaml -f compose.local-model.yaml stop api
docker stop energytool-llm-local
```

Кеш весов и данные существующего backend сохраняются. Повторный запуск — те же две команды из раздела запуска.

Официальные сведения: [модель](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M), [Docker](https://docs.ollama.com/docker), [совместимый API](https://docs.ollama.com/api/openai-compatibility), [локальный режим](https://docs.ollama.com/faq).
