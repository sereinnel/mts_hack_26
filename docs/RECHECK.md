# Повторная проверка проекта

Проверенная база: `856dcfb` (`feature/ai`); коммит `85a0fb6` уже входит в доступную локально `origin/main`. Перед этой проверкой рабочее дерево было чистым. Этот этап выполнялся без обращения к реальному API модели и без перезапуска рабочих сервисов. Последующее подключение настоящей локальной Qwen описано отдельно: [LOCAL_MODEL.md](LOCAL_MODEL.md), результаты — [AI_QUALITY.md](AI_QUALITY.md).

## Найдено и исправлено

1. Оборванный HTTP-ответ (`IncompleteRead` и другие `HTTPException`) обходил обработку отказов модели. Теперь преобразуется в обезличенный `LLMError`, который обрабатывается существующим fallback.
2. При `HTTPError` поток ответа оставался открытым. Теперь он закрывается перед возвратом обезличенного кода ошибки.
3. Экспорт с `--overwrite` мог изменить исходник через символическую или жёсткую ссылку. Символические ссылки отклоняются до записи; замена файлов выполняется через временный файл и не изменяет цель жёсткой ссылки.
4. Два одновременных хода одной сессии могли сохранить несовместимые полные снимки фактов. Воспроизведено: ответ про предприятие завершался после ответа про цель и удалял `goal`. По явному согласованию с владельцем backend весь ход помещён под lock конкретной сессии. Тест также проверяет, что другой session_id продолжает обрабатываться параллельно.

Защита ходов использует память одного процесса и соответствует текущему запуску Uvicorn без нескольких workers. Для нескольких процессов или реплик необходим отдельный механизм общей координации; этот режим не проверялся.

## Что остаётся вне подтверждённого результата

- Настоящие ответы конкурсного API, его задержка и точность семантического Critic. Локальная Qwen проверяется отдельно; её результаты не переносятся на конкурсную модель.
- Ручная проверка интерфейса в браузере: здесь выполнены JS-проверки и тесты клиентского API/хранилища.
- Конкурсный `solution.py` и итоговый ZIP: их подготовку ведёт backend-разработчик. Проверен экспорт AI-модулей, не готовый конкурсный сабмит.

Качество extractive-консультации по-прежнему нужно оценивать отдельно: количество прошедших технических тестов не подтверждает полноту каждого ответа. См. [AI_QUALITY.md](AI_QUALITY.md).

## Проверка перед коммитом: 16 ноября 2026

Повторно прошли полный набор (117 тестов, 63 подпроверки), 103 AI-теста на Python 3.11 и 9 frontend-тестов в Node 22. Проверены синтаксис Python 3.11, неизменность публичной сигнатуры `answer_turn`, отсутствие зависимостей AI от backend/FastAPI/SQLite, изолированный экспорт корневых модулей и `git diff --check`.

Повторный запуск локальной Qwen использует существующие контейнер и кеш. В локальном профиле исправлена передача выбранной модели и порта: Compose получает их через `--env-file data/local_model.env`. Проверены конфигурации по умолчанию и с другими значениями; API остаётся на loopback. Основной `compose.yaml`, API-маршруты и общие зависимости не менялись.

В 66 предназначенных для Git файлах не обнаружены закрытая БЗ, веса, индексы, окружение, SQLite, презентация или шаблоны настоящих секретных ключей. Игнорируемые артефакты в `data/` не входят в коммит. Технические проверки не заменяют оценку качества консультаций; известные ограничения перечислены в [AI_QUALITY.md](AI_QUALITY.md).

Дополнительно выполнен настоящий вызов экспортированного `answer_question` из временной папки вне репозитория, с Python `-S`: генерация и Critic проходят через локальную Qwen, возвращается текст с реальными ID, зависимостей от приложения нет. Содержательные замечания по диалогу оценки стоимости сохраняются и явно зафиксированы; проверка контракта не объявляется проверкой безошибочности модели.
