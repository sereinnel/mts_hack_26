# Автономный AI/RAG baseline

## Статус и границы

`ai/` — импортируемый синхронный Python-модуль, совместимый с Python 3.11 из общего Dockerfile. Новых зависимостей в `requirements.txt` нет. FastAPI, SQLite и frontend не используются. Импорт не читает файлы и не обращается к сети.

По умолчанию `AI_MODE=extractive`: воспроизводимый локальный baseline с маршрутизацией, поиском и извлечением фрагмента. В этом режиме внешние API не вызываются. Ответ состоит из исходного абзаца либо элемента списка и служебных фраз.

Подготовлен необязательный `AI_MODE=llm`: генерация по найденным фрагментам, проверка структуры/ID/чисел и отдельный вызов Critic. Режим проверен на имитациях ответов; доступа к API организаторов пока нет, реальное качество модели и совместимость сервера не проверены. Эмбеддер и реранкер ещё не подключены. Это не законченная мультиагентная система.

## Публичный интерфейс

```python
from ai.consultant import answer_turn

result = answer_turn(
    message="Хотим автоматизировать учёт. С чего начать?",
    history=[],
    session_facts={},
    debug=True,
)
```

Результат — обычный `dict` с полями `answer`, `stage`, `source_ids`, `route`, `updated_facts`, `proposed_action`, `debug`. Сигнатура и типы соответствуют [командному контракту](API_CONTRACT.md#3-согласованный-ai-контракт-реализован-автономно-подключение-к-backend-впереди).

- `history`: список `{"role": "user" | "assistant", "content": str}` до текущего сообщения. Дополнительные поля сообщений игнорируются. Для конкурсных тестов поддерживается история внутри `message` с отдельными строками `Пользователь:` и `Ассистент:`; ответ относится к последней реплике пользователя.
- `updated_facts`: полный глубокий снимок `session_facts`. Входные объекты не изменяются; новые факты в этой версии не извлекаются. Решение о сохранении результата принимает вызывающий код.
- `stage`: в baseline используются `discover`, `qualify`, `handoff`. `recommend` остаётся допустимой стадией контракта для дальнейшего подбора решений.
- `route`: `simple` для приветствия/отсутствия БЗ, `rag` для ответа из источника, `clarify` для уточнения, `handoff` для предложения специалиста.
- `source_ids`: исходные относительные пути **использованных** Markdown/TXT-документов, включая каталоги. Список найденных кандидатов не выдаётся за использованные источники.
- `proposed_action="offer_lead"`: предложение обратиться к менеджеру. Функция не создаёт заявки и не подтверждает согласие на обработку данных. Явный отказ от контактов учитывается по пользовательской истории до изменения решения пользователем.
- `debug`: при `False` всегда `None`; при `True` — время, причина маршрута, тема, ID найденных/использованных фрагментов и результат проверки. Содержимое истории, факты и исходный текст вопроса в debug не копируются.

Контекст поиска включает недавние реплики пользователя и, для коротких ответов, последний вопрос ассистента. Например, вопрос о ценовой категории помогает понять реплику «четвёртая». Утверждения ассистента не считаются источником продуктовых или клиентских фактов.

Пустое сообщение, некорректная история или явно заданный несуществующий путь БЗ вызывают исключение. Отсутствие настройки БЗ — штатный режим с уточняющим ответом. При явно запрошенной генерации без настроенного API возникает `LLMConfigurationError`, а не имитация успешного вызова модели.

## База знаний и индекс

Поддерживаются ZIP с Markdown/TXT и каталог таких файлов. ZIP читается в памяти без распаковки. ID источника — путь относительно корня каталога/архива. Конкретные документы кейса в исходники не встроены.

Поиск объединяет BM25 и символьный TF-IDF через Reciprocal Rank Fusion. Используются простая нормализация русских окончаний, небольшой словарь поисковых синонимов и фильтр темы по заголовкам. Это лексический гибрид, **не** BM25 + BGE-M3.

Документы разбиваются по заголовкам и абзацам, а не обрезаются до начала файла. Мягкий размер фрагмента — 1400 символов; таблицы сохраняются целиком, чтобы не терять подписи столбцов. В ответах baseline таблицы не используются. Списки разбиваются по элементам. Стабильные ID фрагментов содержат ID документа и порядковый номер.

`Critic` проверяет принадлежность цитаты найденному фрагменту и реальность ID. Разделы «Чего утверждать нельзя» исключаются из ответа. Это проверка извлечения: она не доказывает, что фрагмент полностью отвечает на вопрос, и не заменяет будущую семантическую проверку.

В `AI_MODE=llm` используется дополнительный Critic из `ai/generation.py`: отдельно оцениваются подтверждённость, ответ по существу, учёт контекста и корректное обращение с заявками/контактами. Ошибка API, некорректный JSON или отрицательный вердикт отбрасывают черновик и возвращают baseline/уточнение. Отказ от черновика не доказывает релевантность запасной цитаты. Генератор и Critic используют одну модель с разными промптами: их ошибки могут совпадать. Проверка наличия чисел не проверяет единицы измерения и условия применимости.

Переменные модельного режима: `LLM_BASE_URL` (корень API), `LLM_MODEL`, `LLM_API_KEY`, необязательный `AI_LLM_TIMEOUT_SECONDS` (по умолчанию 25 секунд на HTTP-вызов). Поддерживаются алиасы из примера организаторов. `AI_MODE=extractive` остаётся безопасным режимом по умолчанию без сетевых вызовов. `.env` автоматически не читается. Секреты не выводятся в debug.

Запуск из корня репозитория, без сервера:

```bash
python -m scripts.build_index \
  --kb 'Данные-20261109T121228Z-1-001/Данные/knowledge-base.zip' \
  --output indexes/energytool.json

AI_INDEX_PATH=indexes/energytool.json python -c \
  'from ai.consultant import answer_turn; print(answer_turn("Какие задачи решает платформа учёта?", [], {}, debug=True))'
```

Для разработки можно указать `AI_KB_PATH` вместо `AI_INDEX_PATH` и работать без сохранённого индекса. Приоритет: `AI_INDEX_PATH`, затем `AI_KB_PATH`, затем `DATA_DIR/knowledge-base.zip` (также `knowledge_base.zip` или `kb.zip`). `DATA_DIR` по умолчанию — `data`. `.env` модуль самостоятельно не загружает: переменные передаются процессу вызывающим кодом.

Кэшируются только данные и поисковые структуры БЗ; история сессий не кэшируется. Изменение файла БЗ/индекса или состава и метаданных файлов каталога обновляет кэш. После изменения БЗ сохранённый JSON-индекс нужно перестроить; при заданном `AI_INDEX_PATH` исходная БЗ не перечитывается. Не менять БЗ одновременно с обработкой запросов.

Материалы `Данные*/`, презентация `МТС_*.pdf`, каталоги `indexes/`, `knowledge_base/` и `data/` исключены из Git и Docker-контекста. JSON-индекс содержит текст закрытой БЗ, отчёт оценки — ответы: их нельзя коммитить или публиковать.

## Проверка без FastAPI и дополнительных пакетов

Тестовые корпуса полностью синтетические и не содержат копий материалов кейса:

```bash
PYTHONPATH=tests python -m unittest test_ai_contract test_retrieval test_facts test_generation test_quality_eval -v
```

Проверяются контракт, независимость импорта от backend, отсутствие изменения входных объектов, изоляция фактов, обработка контекста, отказ от контактов, поздние разделы документов, поиск с опечаткой, сохранение ID, обновление кэша и полный цикл CLI. Модельные тесты используют только заглушки и проверяют протокол, структуру ответа, отбрасывание выдуманных источников/чисел, реакцию на вердикт и ошибки. Они не измеряют реальную способность LLM рассуждать или проверять смысл.

Локальный прогон предоставленных вопросов:

```bash
python -m scripts.eval_ai \
  --kb 'Данные-20261109T121228Z-1-001/Данные/knowledge-base.zip' \
  --questions 'Данные-20261109T121228Z-1-001/Данные/demo_questions.csv' \
  --output data/ai_eval.json
```

Команда сохраняет ответы, ID и диагностику локально, а в терминал выводит сводные показатели. Она не создаёт конкурсный `submission.csv`. Количество ответов с источниками и задержка не являются оценкой правильности ответа. Для проверки поиска можно передать `--labels path/to/private-labels.json`: объект `{"question-id": ["relative/document.md"]}`. Тогда считаются recall по источникам и MRR среди кандидатов первых 8 фрагментов. Полноту и качество консультации надо оценивать отдельно.

Оценка качества вынесена в `scripts.eval_quality`. Правила, предварительные результаты разбора 18 ответов и команды будущего прогона на модели: [AI_QUALITY.md](AI_QUALITY.md). Без разметки или явно включённого API-судьи ответы получают статус `pending`; искусственные оценки не создаются.

## Передача backend-разработчику

`backend/main.py`, `backend/db.py` и `backend/ai_adapter.py` в этой работе не меняются. Нынешний HTTP API продолжает использовать mock/прежний интерфейс. Прямая установка `AI_FUNCTION=ai.consultant:answer_turn` пока несовместима с адаптером.

Для интеграции backend-разработчику требуется:

1. В своём адаптере вызывать `answer_turn(message=question, history=history, session_facts=facts, debug=debug)`; синхронную функцию при вызове из async-кода выполнять в рабочем потоке.
2. Организовать передачу и сохранение `updated_facts` в рамках конкретной сессии. Новый диалог передаёт пустые историю и факты.
3. Согласовать отображение `source_ids` в существующие `sources` и семантику `intent`; автоматического равенства `route`, `stage` и `intent` нет. Сохранить нынешние HTTP-маршруты и формат запросов.
4. Обрабатывать `offer_lead` как предложение открыть форму; создавать заявку только через существующий пользовательский сценарий.
5. Добавить `COPY ai ./ai` в общий Dockerfile и доступ к приватному индексу/БЗ через конфигурацию и том. Сейчас образ содержит только `backend/`; закрытую БЗ в образ не включать.

Готовая задача с критериями приёмки: [BACKEND_AI_TASK.md](BACKEND_AI_TASK.md).
