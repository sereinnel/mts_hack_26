# Задача backend: подключение автономного AI-модуля

Ветка: `feature/backend`. Цель: заменить текущий mock/прежний вызов `consult(question, history)` на согласованный `answer_turn`, сохранив существующие HTTP-маршруты и запросы.

Статус после интеграции: вызов `answer_turn`, сохранение фактов по сессии и копирование `ai/` в Docker выполнены в `main`. AI теперь извлекает явно сообщённые `industry` и `goal`. Ниже сохранён исходный список для проверки остальных критериев; детали актуального поведения — в [AI_MODULE.md](AI_MODULE.md).

## Точка интеграции

```python
from ai.consultant import answer_turn

result = await asyncio.to_thread(
    answer_turn,
    message=question,
    history=history,
    session_facts=session_facts,
    debug=False,
)
```

Функция синхронная, блокирующую работу нельзя выполнять непосредственно в event loop. `history` содержит реплики до текущего `message`, только `role` и `content` обязательны.

Результат: `answer`, `stage`, `source_ids`, `route`, `updated_facts`, `proposed_action`, `debug`. Допустимые стадии: `discover`, `qualify`, `recommend`, `handoff`. AI не зависит от backend и не создаёт заявки.

## Что реализовать

1. Адаптировать `backend/ai_adapter.py` к именованным аргументам `answer_turn`. Сохранить прежний режим mock при отсутствии настройки AI. Выполнено: `AI_FUNCTION=ai.consultant:answer_turn` поддерживается.
2. Хранить `session_facts` в общей SQLite с привязкой к сессии. `updated_facts` — полный новый снимок, не частичный патч. Сохранять его после успешного AI-хода. Выполнено; AI также добавляет явно сообщённые тип организации и цель.
3. Сохранять внутренние метаданные AI-ответа: `stage`, `route`, `proposed_action`, реальные ID источников. Миграция должна сохранять существующие сессии, сообщения и заявки. Новый диалог получает пустые историю и факты.
4. Обеспечить последовательность обновлений одной сессии: параллельные запросы не должны затирать факты и перемешивать историю. Независимые сессии не блокируют друг друга на время вызова модели. Не держать транзакцию SQLite открытой во время сетевого запроса. Выполнено при повторной проверке: весь ход сериализуется по session_id в текущем одном worker Uvicorn; для нескольких workers/реплик понадобится общая координация.
5. В существующем HTTP-ответе использовать `sources = result["source_ids"]`, `answer = result["answer"]`. Для `intent` до отдельного согласования сохранить прежний fallback `"unknown"`; `route` и `stage` не считать синонимами `intent`. Добавление полей в HTTP-ответ и отображение `offer_lead` во frontend согласовать с frontend-разработчиком отдельным изменением контракта.
6. `proposed_action="offer_lead"` означает только предложение пользователю. `POST /api/leads` вызывается по явному действию пользователя через существующую форму с согласием. Нельзя автоматически создавать заявку или переносить контакты из истории в согласие.
7. `debug` по умолчанию выключен. Не передавать произвольный публичный параметр запроса в AI-debug до согласования доступа и HTTP-схемы. Не логировать ключи, сырые промпты или закрытую БЗ.
8. В Dockerfile добавить `COPY ai ./ai`. БЗ/индекс подключать приватным томом, путь передавать через `AI_INDEX_PATH` или `AI_KB_PATH`. Закрытую БЗ и ключи не включать в образ, Git и PR. Новых Python-зависимостей у текущего AI нет.
9. Конкурсный `solution.py` при необходимости вызывает то же AI-ядро. Каждый тест-кейс получает собственные пустые факты; переданную историю использовать внутри одного кейса. Состояние SQLite между вопросами не использовать.

## Ошибки и режимы

- Существующее поведение API при ошибке AI сохраняется: пользовательское сообщение записывается, сервер возвращает согласованный `502`, не создаёт сообщение с выдуманным ответом и не сохраняет частичные факты.
- По умолчанию `AI_MODE=extractive`: ответ из локальной БЗ, без внешних API. БЗ без настройки даёт штатное уточнение, явно ошибочный путь вызывает исключение.
- Необязательный `AI_MODE=llm` требует адреса, модели и ключа совместимого API. Конкурсная платформа передаёт их автоматически; личный ключ не нужен. Локальная проверка с настоящей Qwen и отдельным Docker-профилем описана в [LOCAL_MODEL.md](LOCAL_MODEL.md). Наличие переменных окружения не доказывает доступность модели.
- Полный AI-контракт и команды проверки: [AI_MODULE.md](AI_MODULE.md), [API_CONTRACT.md](API_CONTRACT.md).

## Критерии приёмки

- Контрактные тесты адаптера проверяют точные аргументы вызова и преобразование `source_ids` в `sources`.
- API-тесты проверяют два хода с передачей/сохранением фактов, изоляцию двух сессий, чистый новый диалог и сохранение истории закрытой сессии.
- При двух одновременных запросах одной сессии нет потери обновлений и повторного добавления текущего сообщения в AI-history.
- При ошибке AI сохраняется текущая пользовательская реплика, а факты и assistant-ответ не обновляются частично; ключи и текст БЗ не попадают в HTTP-ошибку.
- `offer_lead` не увеличивает число заявок. Отправка формы с `consent_to_contact=false` по-прежнему отклоняется.
- `debug=False` не раскрывает диагностику. Нынешние маршруты и тела запросов не изменены.
- В контейнере импортируется `ai.consultant`, индекс доступен через том; в слоях образа нет закрытой БЗ и секретов.
- Проходят существующие `tests/test_api.py` и автономные AI-тесты. PR направлен в `main`; описание перечисляет изменения хранения/адаптера и результаты проверок.
